<h1 align="center">班级信息管理系统</h1>

<p align="center">
  面向班级、年级、院系等基层单位的轻量信息管理系统：名单、考勤、成绩、通知、投票、收集、办件、消息推送。<br>
  为弱网与手机端优化，一条命令部署，同一组镜像可以服务多个单位。
</p>

![首页](docs/images/home-dashboard.png)

## 为什么是它

- **一个站点覆盖日常**：学生名册、课堂点名与抽签、考勤、成绩、通知公告、
  投票表决、投票收集、请假与证明、数据导出、操作日志，都在同一套权限体系里。
- **弱网与手机优先**：首屏资源按需加载，图片进入视口才下载，表格在手机上可滑动；
  页面可以「添加到主屏幕」，接近原生应用。
- **隐私内置**：照片与附件经鉴权接口下发；名单与审批页盖有「姓名@班级 日期」水印；
  隐私数据不进镜像，全部落在可备份的数据卷里。
- **登录方式可叠**：密码、通行密钥（指纹 / 面容 / Windows Hello）、
  可选二次验证（邮箱验证码 / TOTP），另备一次性恢复码。
- **可复制**：同一组镜像、换一份配置就是另一个单位的站点，互不影响。

## 功能

| 模块 | 说明 |
|---|---|
| 学生信息 | 筛选、排序、详情、备注、批量导入 Excel 与照片 |
| 考勤 | 点名自动跳过已批准请假，结果可改、可备注（按备注搜索）、可导出 |
| 分类统计 | 性别、民族、政治面貌、宿舍、贫困生、高考分数段 |
| 成绩 | Excel 录入、预览核对、逐格改分、按考试名搜索，学生只看自己的 |
| 通知公告 | Markdown 正文、附件、已读名单、RSS 订阅；文件公开按标题或文号片段搜索 |
| 投票表决 | 多题、单选 / 多选、记名 / 不记名、定向范围、复用旧卷、按标题搜索 |
| 投票收集 | 单选/多选/短文本/长文本/图片/评分，每人多份、竞争名额、匿名、撤回、复用旧卷与范围、Excel 导出 |
| 办事中心 | 请假、电动车通行证、证明开具、意见反馈，带受理与补正 |
| 数据导出 | 名单 Excel 或带水印的个人信息表 PDF，管理员审批 |
| 消息 | 站内信必达；浏览器通知、Bark、邮件、Webhook 可选 |
| 系统管理 | 账号与角色、IP 封禁、操作日志、文件访问溯源、数据体检、资料分类排序 |

## 适用范围与定制

系统不只为单个班级设计。班级、年级、院系这类基层单位共用同一套结构——
成员名册、按角色的权限、通知与投票、办件审批、数据导出；同一组镜像可以部署多份实例，
分别服务不同单位，数据彼此隔离。

办件的业务差异很大：请假、证明、电动车通行证、意见反馈只是内置的几类，
不同单位往往有自己的表单、审批链和产出材料。**新增或修改办件需要改代码**，不是配置能完成的。
如需有偿个性化定制办件，或进行其他定制化开发，请联系开发者：
[hanyu-zh@foxmail.com](mailto:hanyu-zh@foxmail.com)。

## 快速开始

镜像公开托管在 GHCR，服务器上只需要 `docker-compose.yml` 与 `.env`：

```bash
git clone https://github.com/GZYZhy/class-oa.git
cd class-oa

cp .env.example .env
# 至少填写：SITE_NAME、PUBLIC_BASE_URL、BOOTSTRAP_PASSWORD

docker compose up -d
curl -s http://127.0.0.1:8000/api/health
```

首次启动后用 `admin` + `BOOTSTRAP_PASSWORD` 登录，按引导导入学生并指定一名管理员，
临时账号会当场删除。完成后清空 `BOOTSTRAP_PASSWORD` 并重启后端。

前端默认监听 `8080`，后端只绑定 `127.0.0.1:8000`。建议在前面放一层 HTTPS 反向代理，
完整步骤见 [部署与运维](docs/serve.md)。

## 技术栈

- **前端**：Vue 3、Element Plus（按需引入）、Vite
- **后端**：FastAPI、SQLAlchemy 2.0、SQLite（可选 MySQL）
- **部署**：Docker Compose，nginx 托管静态资源并反代 `/api`
- **发布**：推送版本标签后 GitHub Actions 先跑测试再构建镜像并推送 GHCR，服务器 `pull` 即更新

## 测试

```bash
./runTest.sh
```

后端用 pytest 为每个用例启动真实后端进程与临时数据库；前端用 Vite 的 SSR 管道
真实渲染组件并断言页面文案。两套测试都不会读写 `data/` 里的真实数据。
CI 在提交到 `main` 或发起合并请求时跑同一套测试；推送 `vX.Y.Z` 标签时先过测试再构建镜像。
