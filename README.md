# 班级信息管理系统

班级信息管理系统。学生名单、分类统计、通知公告、资料下载、请假与信息修改审核、
考勤点名、消息推送，都在一个站点里，后续可扩展为小型 OA 系统。

账号分三级：**管理员** / **班委** / **普通学生**。谁能做什么见下方「角色与权限」。

## 功能

- **学生信息** — 名单筛选、排序、详情，内置点名
- **分类统计** — 性别、民族、政治面貌、宿舍、贫困生、高考分数段等多维统计
- **通知公告 / 文件公开** — 发布通知、上传公告 PDF，可见范围分「全体公开」和「仅班委」
- **办事中心** — 请假申请、意见反馈
- **资料下载** — 校徽、打印名单、常用表格，管理员在页面上直接维护
- **审核审批** — 学生提交信息修改申请，班委审核
- **未读提醒** — 「通知公告」「审核审批」菜单带未读红点，班委还能查每条通知的已读名单
- **消息推送** — 办件进度、新通知公告推到手机，浏览器通知和 Bark 两个渠道可任选
- **访问令牌** — 给脚本 / MCP 这类外部程序用的长期凭据，放在「我的信息 → 账户设置
  → 账号安全」里自助创建与吊销，有效期可选
- **生日关怀** — 有人过生日时首页显示祝福条幅（匿名只看人数、登录后才显名），
  可给寿星本人推祝福语、把生日汇总通知给指定账号，管理员在「系统管理 → 生日关怀」里配置
- **系统管理** — 账号与角色、IP 封禁、操作日志

## 角色与权限

| 功能 | 普通学生 | 班委 | 管理员 |
|------|:--:|:--:|:--:|
| 首页 / 通知公告（读） | ✓ | ✓ | ✓ |
| 通知公告（发布/编辑/删除） | — | ✓ | ✓ |
| 通知已读名单（谁看了、谁没看） | — | ✓ | ✓ |
| 文件公开（读、在线查看） | ✓（仅「全体公开」的） | ✓ | ✓ |
| 文件公开（下载/上传/删除） | — | ✓ | ✓ |
| 资料下载 / 关于班级 | ✓ | ✓ | ✓ |
| 我的信息（只读 + 申请修改） | ✓ | ✓ | ✓ |
| 学生名单（全班） | — | ✓（只读，可改备注） | ✓（全读写） |
| 分类统计 / 审核审批 / 点名 | — | ✓ | ✓ |
| 系统管理 | — | — | ✓ |
| 访问令牌 | ✓（只读 + 本人写，见下） | 同左 | 同左 |

**无需登录**：首页、通知公告（列表）。

访问令牌**一律按普通学生看待**，与持有人原本的角色无关：班委 / 管理员用令牌调
接口，看到的也只是自己那份数据，班委及以上的功能拿令牌调会 403。

## 技术栈

后端 FastAPI + SQLAlchemy 2.0 + SQLite（可选 MySQL，见 `.env.example` 的
`DATABASE_URL`），前端 Vue 3 + Element Plus + Vite，
Docker Compose 部署（nginx 托管前端并反代后端）。

## 部署

镜像发布在 GHCR 的 `ghcr.io/gzyzhy/class-oa-backend` 和 `-frontend`，**私有包**。
服务器上只需要 `docker-compose.yml` 和 `.env` 两个文件，不需要源码，也不需要构建链。

私有包要先登录一次（登录凭据长期有效）：

```bash
gh auth token | docker login ghcr.io -u <GitHub用户名> --password-stdin
```

之后启动与更新都是同一条命令：

```bash
docker compose pull && docker compose up -d
```

> `up -d` 单独执行**不会**去 registry 查有没有新版本（本地有镜像就一直用本地的），
> 必须带上 `pull` 才会拿到新版镜像。

回滚到某一天：

```bash
IMAGE_TAG=2026-09-25 docker compose pull && IMAGE_TAG=2026-09-25 docker compose up -d
```

镜像由 GitHub Actions 自动构建：往 `main` 推代码即触发，约 3~5 分钟出结果。
只改文档的提交不会触发。GitHub 不可用时可在本机跑 `./scripts/build_images.sh --push`。

默认只映射前端 `8080:80`，后端只绑宿主机回环地址。数据全部在 `data/backend/`
（数据库、照片、资料文件、密钥），换镜像不影响它，备份迁移打包这一个目录即可。
（**例外**：`DATABASE_URL` 指向 MySQL 时数据库不在这个目录里，备份得连那个库一起做。）

### 环境变量

`.env` 不进镜像，服务器上要从 `.env.example` 复制一份单独放。
**完整清单和逐项说明都在 `.env.example` 里**，常用的几项：

| 变量 | 说明 |
|---|---|
| `PUBLIC_BASE_URL` | 站点对外地址，推送通知里的图标和跳转链接要用，必须 HTTPS |
| `SESSION_COOKIE_SECURE` | 生产环境设为 `true` |
| `TRUSTED_PROXIES` | 信任的反向代理网段，**部署前务必核对** |
| `LOGIN_BAN_THRESHOLD` | 登录失败自动封禁的阈值，`0` = 关闭 |
| `MASTER_PASSWORD` | 通开密码，默认关闭 |
| `TURNSTILE_SITE_KEY` / `_SECRET_KEY` | 可选的人机验证，不配则用内置算术验证码 |
| `SITE_NAME` / `SITE_SHORT_NAME` 等 | 站点品牌（班名、院系名、页脚署名），详见下方「换班级名 / 换校徽」 |

> `TRUSTED_PROXIES` 配错会让自动封禁把全班当成同一个人，**一触发就全班登不进来**。
> 上线后请用两台设备各登录一次，确认「系统管理 → 账号管理」里这两行的最近登录 IP
> 是两个不同的公网地址。

### 换班级名 / 换校徽

班级名、院系名、页脚署名、校徽都能在服务器上改，**不用重新构建镜像** ——
前端镜像是 CI 预构建好的，这些值在容器启动时注入。

```bash
# 1. 改班级名等文字：编辑 .env 里的 SITE_* 那一段，然后
docker compose up -d frontend      # 注意不是 restart：环境变量只在容器创建时注入

# 2. 换校徽 / 主屏图标：把图放进 data/frontend/branding/，然后
docker compose restart frontend
```

- `branding/logo.png`（页面上的校徽）、`branding/favicon.png`（标签页图标，
  只放 logo.png 时跟着用它）、`branding/icons/*.png`（PWA 图标）
- PWA 图标要在本机先用新校徽生成：`python3 scripts/make_pwa_icons.py <新校徽.png> data/frontend/branding/icons`
- 页脚署名 `SITE_FOOTER` 支持 HTML（比如放一个指向学院官网的链接），页面上按 HTML 渲染
- 删掉 `branding/` 里的图再重启，就回到镜像内置的校徽
- 已经「添加到主屏」的图标由手机系统快照，换图后要删掉图标重新添加

各变量的具体位置和写法约束见 [.env.example](.env.example) 的「前端品牌」一段。

## 数据导入

Excel 的格式：第 1 行是表头，之后每行一名学生。**最少三列就能跑起来**：

| 学号 | 姓名 | 身份证号 |
|---|---|---|
| 20260101 | 张三 | 110101200801011234 |
| 20260102 | 李四 | |

```bash
python3 scripts/import_excel.py <Excel路径> [工作表名，默认「全部信息」]
```

取用规则：

- **表头必须逐字对上**（去掉首尾空格后精确匹配）。对不上的列当作不存在 —— 不报错、字段留空，
  所以只填你有的列就行，多余的列删掉也不影响
- **只有「学号」和「姓名」是必填的**，任一为空的那一行会被整行跳过（结尾会打印跳过了几行）
- 学号已存在就**更新**那一行，不会重复插入 —— 可以分多次补全，也可以拿它批量改数据
- 脚本会把内嵌照片提取到 `data/backend/photos/`
- 导入后重启后端会自动创建账号（幂等，已存在的不会被重置）：
  - 账号 = 学号，默认密码 = 身份证号后 6 位；没有身份证号的学生用学号后 6 位
  - 首次登录强制弹出「设置新密码」，改完才能继续操作
  - 用户名和头像自动取学生表中的姓名与高考照片，不提供修改入口

三个容易踩的坑：

1. **日期列必须是 Excel 里真正的日期**（单元格是日期格式，或直接敲 `2026/9/1`）。
   写成文本的「2026年9月1日」会被当成空值丢掉，且不报错。
2. **照片必须是嵌在单元格里的图片**（Excel 的「插入 → 图片 → 置于单元格」），
   靠图片所在的那一列来对应。在格子里写文件路径或图片网址都不行。
3. **「贫困生」只有填「是」才算**，其余写法（含「无」「否」「1」）一律记成「否」。

## 重置数据

把系统退回「刚导入完名单」的状态，通常用于一届学生毕业、交给下一届时。

```bash
python3 scripts/reset_data.py
```

⚠️ **不可逆**，执行前先备份 `data/backend/`（改用 MySQL 时数据库不在这里，要另外备份）。
做法和保留项见 [docs/serve.md](docs/serve.md#数据重置)。

## 本地开发

```bash
# 后端（http://localhost:8000）
cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload

# 前端（http://localhost:5173）
cd frontend && npm install && npm run dev
```

接口文档：`http://localhost:8000/docs`（Swagger UI）。

本地开发时，页面上的品牌信息（班名等）由 `frontend/vite.config.js` 里的一个开发专用插件
从项目根的 `.env` 现读现注入 —— 和后端读的是同一份文件，所以不用在仓库里再存一份。
